\newcount\@ctoc@col
\newcommand\CompactTableOfContents{%
	\begingroup
		\@ctoc@col=\z@\parfillskip\z@\@plus1fil
		\renewcommand*\numberline[1]{##1\nobreakspace}%
		% the entries are boxes of the same width, three in a row
		\def\l@section##1##2{%
			\ifnum\@ctoc@col=3 \par\@ctoc@col=\z@\fi
			\advance\@ctoc@col\@ne
			\makebox[.325\linewidth][l]{##1\,\textcolor{@softgray@b}{##2}}%
		}%
		\let\l@subsection\@gobbletwo
		\let\l@subsubsection\@gobbletwo
		\let\l@paragraph\@gobbletwo
		\par\noindent\textcolor{@softgray}{\rule{\linewidth}{.3pt}}\par\nobreak\vspace{.6ex}
		\small\parindent\z@\parskip.25ex\parfillskip\z@\@plus1fil\relax
		\@starttoc{toc}\par
		\vspace{.2ex}\textcolor{@softgray}{\rule{\linewidth}{.3pt}}\par
	\endgroup
}

As this package is constantly work in progress, the concrete dependencies may change any time.
At the moment, it loads \href{https://www.ctan.org/pkg/pgf}{\TikZ}, which loads a lot of other packages (e.g.\ \href{https://www.ctan.org/pkg/xcolor}{xcolor}), and \href{https://www.ctan.org/pkg/etoolbox}{etoolbox}.

\section{Usage}\label{Usage}

If you just want a penguin, import the package and start with the following:
\begin{tcblisting}{title={One small penguin},externalize listing=small-pengu}
\begin{tikzpicture}
	\pingu
\end{tikzpicture}

	\pingu[left wing wave, right wing grab,
	       eyes shiny, cup]

Please note, that \say{left} and \say{right} have been chosen from the penguin-perspective.

\paragraph{The Layers}\label{internal:layers}
The parts of a penguin which are behind or in front of the rest are drawn in five layers, which belong to the package and are the same for every penguin. The figure shows them for one penguin; each plane contains only what is drawn in this layer (the penguin on the right is the sum of all planes). When a penguin is finished, its five layers are put into one box of a sixth layer, the stack layer, one above the other, and are empty again. So a picture needs six layers, no matter how many penguins it contains, and a penguin which is drawn later is above all parts of an earlier one. With \keyref{:back}, the order of the five layers is reversed. Only the glow of a lightsaber is not stacked: it has a seventh layer, which is shared by all penguins of the picture and lies above all of them.

\subsection{Anchors and Placement}\label{mrk:anchors}
The origin of a penguin sits at its right shoulder. \keyref{anchor} moves the
penguin so that another of its points lands on the origin instead:
\begin{tcblisting}{title={Two anchors},externalize listing=anchor-pengu}
\begin{tikzpicture}
	\pingu[anchor=belly]
	\pingu[anchor=head,xshift=3cm]
	\foreach \x in {0,3cm}
	  \draw[red] ([xshift=\x]-2mm,0) -- +(4mm,0)
	             ([xshift=\x]0,-2mm) -- +(0,4mm);
\end{tikzpicture}
\end{tcblisting}
Besides the names listed at \keyref{anchor} any point works, e.g.\ |anchor={(1cm,-5mm)}|.

Anchors refer to the \textit{silhouette of the body}; gadgets, wings, and feet
may stick out of it, so the anchors do not change with the extras a penguin
wears. Its nine outer anchors are coordinates as well (prefixed by
|<|\keyref{name}|>-|): |center|, |north|, |south|, |east|, |west|,
|north east|, |north west|, |south east|, and |south west|. The anchor in use
is available as |<|\keyref{name}|>-anchor| and, together with the silhouette,
shown by \keyref{meta-dots}.

Those outer anchors are what \keyref{right of}, \keyref{left of},
\keyref{above of}, and \keyref{below of} use, each taking the name of the other
penguin and, after a colon, the distance to keep:
\begin{tcblisting}{title={A row of penguins},externalize listing=relative-pengu}
\begin{tikzpicture}
	\pingu[name=a,wings wave]
	\pingu[name=b,right of=a:5mm,large size]
	\pingu[name=c,left of=a:5mm,small size]
	\pingu[name=d,above of=a:2mm,eyes shiny]
	\pingu[name=e,below of=a:2mm,body=pingu@blue]
\end{tikzpicture}
\end{tcblisting}
\keyref{right of} and \keyref{left of} keep both penguins on the same ground
line, \keyref{above of} and \keyref{below of} center them horizontally. An
\keyref{anchor} passed \textit{after} one of them keeps the target point but
changes which point of the new penguin is moved onto it.

\label{Colors}A lot of options allow for a color to be passed. In general, you can provide any color that \TikZ\ is happy with! Yet, there are some predefined pingu-colors shipped with this package:

\subsection{Setting the defaults}
You do not have to re-state every key.
With \cmdref{pingudefaults} and \cmdref{pingudefaultsappend} (similar, but extends the current options) you can set default-options for all penguins to come:
\begin{tcblisting}{title={Change the mainstream},externalize listing=update-defaults}
\begin{tikzpicture}
	\pingudefaults{wings grab, eyes shiny}
	\pingu
	\pingu[left wing shock, xshift=2.7cm]
\end{tikzpicture}
\end{tcblisting}

\begin{commandexplain}{pingudefaults}{\mand{penguin keys}}
	Sets the given \textit{penguin keys} as defaults for the local group.
	Overwrites any previews defaults (see \cmdref{pingudefaultsappend}).
\end{commandexplain}

\begin{commandexplain}{pingudefaultsappend}{\mand{penguin keys}}
	Appends the given \textit{penguin keys} as defaults for the local group.
	To overwrite these keys, see \cmdref{pingudefaults}.
\end{commandexplain}

\typesetselection{leftwing}. \say{none} is a special wing-position: it omits the drawing of wings (teaser: every selection has a none-option, which prohibits the part from being drawn)!

\subsection{Randomness}
\ValueAnchor{pv:!random}{pingu-magic}{!random}Each selection (like the wings or the eyes) can receive a special command \lpingu{!random}. If given, the penguin will receive a randomly picked component.
Please note, that \textit{none} (the component removing it) will never be picked.
The first line in the example in Box~\say{\nameref{random-penguin}} sets the seed. % we do not externalize this one
\begin{tcblisting}{title={Random Penguin},nameref={Random Penguin},label=random-penguin,float}
\pgfmathsetseed{\number\pdfrandomseed}
\begin{tikzpicture}
	\pingu[wings=!random,eyes=!random,
			left foot=!random,
			bill=!random,
			hairstyle=!random]
\end{tikzpicture}
\end{tcblisting}

In a more general fashion, there is a \keyref{random from} key for completely random penguins.

\keyexplain{random from}{list}{}
	You can pass any list of penguin keys and exactly one of them will be selected. You can nest \keyref{random from}-calls. Please note, that the items are not separated by comma but in braces. The first line in the example sets the seed:% do not externalize
\begin{tcblisting}{}
\pgfmathsetseed{\number\pdfrandomseed}
\begin{tikzpicture}
	\pingu[random from={{eye patch left}{eye patch right}{halo,halo raise=4mm}},random from={{right eye color=pingu@blue}{random from={{bow tie}{gold medal}}}},random from={{eyes=!random}{wings=!random}},body type=legacy]
\end{tikzpicture}
\end{tcblisting}
\endkeyexplain

	       left wing item angle=70]

\subkeyexplain{flag left}{flag left code}{\LaTeX-code}{omitted}
Set the flag code which is effectively the drawing code of the flag.
You can use the styles \lpingu{/pingu/@flag@first} and \lpingu{/pingu/@flag} to inherit the default flag styles and to stay compliant with the modifications of the other macros:
	\begin{tcblisting}{@}
\begin{tikzpicture}
	\pingu[flag left, flag left code={
	  \node[/pingu/@flag@first,
	  	/pingu/@flag={blue}{5mm}]
	  		(upper) at (0,0) {};
	  \node[below,/pingu/@flag={black}{4mm}]
	  	(lower) at (upper.south) {};
	}]
\end{tikzpicture}
\end{tcblisting}
Note that \lpingu{/pingu/@flag} expects two arguments: the color of the flag segment and its thickness.
\endsubkeyexplain

\subsection{Clothes}

Clothes are currently completely work in progress as the goal is to create an elegant way to offer clothes that adapt to the wing positions of the penguin.
Currently there is only one cloth type that may be heavily edited in the course of development\ldots

\subsubsection{The cloak}

A cloak consists of the back, which is drawn behind the penguin, of the collar around the head, of the lining at the front and of the sleeves which cover the wings. Except for \keyref{cloak}, all colors are derived from the main color. The keys of the first version (\texttt{cloak cap}, \texttt{cloak front color}, \texttt{cloak bottom color}, \texttt{cloak wings color}, and \texttt{cloak padding}) still work, they are aliases.

\subsection{How a Penguin is Drawn}\label{internal:draw}
\cmdref{pingu} is the only command that draws, and it does so part by part, from the back to the front. Each part is drawn within a scope whose style \texttt{/pingu/@<part>} is empty by default, so that the sets of Section~\ref{internals} (for example \keyref{:mix} or \keyref{:ghost}) can change a single part. The parts of a penguin which are behind or in front of the rest (\texttt{very-background}, \texttt{background}, \texttt{main}, \texttt{middle}, \texttt{foreground}, in this order) are drawn in six layers which are put one above the other when the penguin is finished, so a penguin which is drawn later is above a penguin which is drawn earlier, wings included. The package option \texttt{manual-layers} lets all penguins of a picture share the layers instead.

\paragraph{The helpers.} Every shape is drawn with one of three helpers: \cmddef{pingu@path} (a path), \cmddef{pingu@block} (a filled shape) and \cmddef{pingu@draw} (a line). They take a color, and draw nothing if it is \cmdref{@pingu@none}. This is the mechanism that lets you hide any part by giving it that color.
\sourcecode{path commands}

\paragraph{The setup.} The group is opened and \lpingu{/pingu/defaults} followed by the given keys are executed. This is why a key never depends on a former penguin. Then the silhouette (\cmdref{pingu@bbox@update}) and the shift of \keyref{anchor} are calculated, and the outer anchors are placed (\cmdref{pingu@place@anchors}).
\sourcecode{pingu setup}

\paragraph{The body and the face.} The body is drawn by the selected body type (\cmdref{@pingu@drawer@bodytype@}), and the belly is clipped to the white of the body. The eyes follow.
\sourcecode{pingu body}

\paragraph{Everything behind the wings.} The clothes behind the penguin (shirts and the back of the cloak), the extras below the head (\implref{extras below}) and the hair come next. The feet are drawn on the \texttt{background} layer unless \keyref{feet front} is set.
\sourcecode{pingu behind}

\paragraph{The wings.} The wings are drawn after the body. Afterwards the coordinates for the items of the wings are calculated from the position of the wings, and the front of the clothes follows (\implref{clothes}).
\sourcecode{pingu wings}

\paragraph{The front.} The bill, the extras above the head (\implref{extras above}) and the items of the wings are the last parts. At last the meta dots (\keyref{meta-dots}) and the code of \lpingu{/pingu/@post} are drawn.
\sourcecode{pingu front}

\subsection{The Wings}\label{internal:wings}
In contrast to the other selections, a wing consists of more than the drawing: the key for the wing, its color, the position of its tip and the angle of the items it holds. \subsection{Extras}\label{internal:extras}
Everything else you can put on a penguin is an \emph{extra}. An extra consists of some keys, a switch \lpingu{\\if@pingu@x@<name>@} and the code to draw. \cmddef{pingu@create@extra} creates all of it: it takes the name, the keys (which call \cmddef{pingu@set@extra} to switch the extra on) and the defaults, which are appended to \lpingu{/pingu/extra defaults} so that every penguin starts with a clean set. Extras behind the body are drawn by \lpingu{\\pingu@draw@eb@<name>} and extras in front of it by \lpingu{\\pingu@draw@ea@<name>}. The lists with the order of the extras (\implref{extras below} and \implref{extras above}) decide what covers what, a later extra is drawn above an earlier one. They are the only place to change the order of two extras, and a new extra has to be added to one of them. The face (glasses, mask, \ldots{}) is in front of the headphones, which are behind the hats, and the pants are behind the belt. This is the cup, an extra below the head:
\sourcecode{cup}
And the halo above the head, which uses a layer for the glow:
\sourcecode{halo}
Extras for the wings are created with \cmddef{pingu@create@wing@extra}, which creates the keys for both wings:
\sourcecode{cane}
All extras are grouped in libraries (\texttt{christmas-lib}, \texttt{hats-lib}, \ldots{}) which are regions of the source, as the map in Section~\ref{internal:draw} shows. A library is only a convenient place to look: nothing is loaded on demand.
